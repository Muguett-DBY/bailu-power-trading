# 交易复盘与持仓

## 适用场景
- 用户要复盘某个月或某几天的交易结果。
- 用户问持仓：中长期覆盖率够不够、日前申报占多少、偏差多大。
- 用户问这个月比全部按实时价买省了还是多花了，原因是什么。

## 需要的输入
- 台账里这段时间的记录：成交（合约）、申报、计量（每天的用电量）。缺计量记录时先请用户提供，或按 trading-ledger 技能记入；没有计量记录就算不出。
- 实时价：计量记录里的「实时均价」；没写时向用户要这段时间的实时加权均价（元/兆瓦时），或从电价表统计（`bailu table "<某天>实时加权均价是多少" <电价表文件>`）。

## 步骤
1. 先运行 `bailu ledger list`（可以加 `from=` 和 `to=`），看这段时间的记录是否齐全：有没有成交、申报、每天的计量。
2. 运行 `bailu review [from=日期] [to=日期] [spot=实时价]`。
3. 读结果，按这个顺序讲：
   - 表格：每天的用电量、合约电量、日前申报、偏差电量和电费。表格原样放进回答。
   - 「持仓」一行：中长期覆盖率、日前申报占多少、合计锁定了多少、偏差电量和偏差率。覆盖率明显低于或高于 100% 时只说明事实和敞口大小，不替用户判断该不该调整。
   - 「归因」一行：比全部按实时价结算节省或多花了多少，其中中长期合约、日前申报各贡献多少。
4. 有实时价的天才算电费。输出里说有几天没有实时价时，把这些天告诉用户。
5. 用户问为什么省或为什么多花：用归因里的两项解释（合约价低于实时价是合约的贡献；日前申报价低于实时价是日前的贡献）。数字都取自命令输出，不要自己算。

## 输出格式
- 第一句：结论（这段时间比全按实时价结算节省或多花了多少，主要来自哪一项）。
- 逐天表格，原样放入。
- 持仓和归因两行，照命令输出的数字。
- 最后：口径说明（中长期和日前按各自的价格结算，偏差按实时价结算；跨多日的合约按天平均分摊）和数据里缺的天数。

## 常见错误与提醒
- 复盘只描述已经发生的，不是对下个月的建议；用户要建议时，把各种选择的后果算清楚（可以用 `bailu calc settlement --message "<用户原话>"`、`bailu calc deviation --message "<用户原话>"`），由用户决定。
- 偏差为负（合约多于用电）时，多出的部分按实时价卖出，这是结果的一部分，照原样说明。
- 结算方式的规则背景见〈现货市场与中长期市场的衔接〉〈偏差电量〉；每天结算依据和账单的口径见〈日清月结、结算依据与结算账单〉。涉及「本省允许偏差是多少」这类问题时，按 policy-lookup 技能查本省文件。
- 台账里的记录不全（例如只有合约没有用电量）时先补台账，不要凭印象补数字。
