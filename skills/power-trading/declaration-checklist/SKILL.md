# 申报检查与申报日志

1. 读取用户的 CSV 或 Excel 曲线，记录表名、行号、列名和单位。核对时间戳、时段数、重复、缺项、排序以及数值解析。检查起止时间和点间隔后再算。确认地区、交易日、品种和约束来源，按 policy-lookup 搜本期申报规则。
2. 用工作表或 Python 实际计算每项约束，按原行记录异常：
   - 负荷或出力按上下限校验。爬坡看连续相邻点的绝对变动；步长的起点和倍数以市场声明为准。
   - 分段报价核对单价、量或累计量的上下限、重复价、段序和买卖方向对应的单调性。
   - 储能确认每段时长、功率、容量、初始 SOC、充放电效率和上下界。按约定的充放电效率逐段累加电量，单段净变化可写为（充电功率 × 充电效率 − 放电功率 ÷ 放电效率）× 时长。用累计变化最小值和最大值与允许的电量上下限反算可行初始区间。未给初始 SOC 时只列区间及上下限检验的结论。
   - 用户问偏差风险时按 deviation-assessment 取对照量、允许范围和考核规则计算。
3. 给结论、每项的通过或未检查状态、异常位置和超出量。缺关键约束时直接列缺失项，全部已给约束通过后说明结论的适用范围。
4. 要准备申报文件时生成标注「待人工确认」的草稿。涉及数据、风险与决策留档的完整任务按 `trading-workflow` 编排。有实际业务回执或用户确认已经申报后，按 `trading-ledger` 追加到 `declarations.csv`。查询历史时按日期筛台账。
