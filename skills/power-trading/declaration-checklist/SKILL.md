# 申报检查与申报日志

## 适用场景
- 用户准备在中长期、日前或实时市场申报电量、曲线或报价，想知道能不能报、哪里不合规。
- 用户给出一条曲线文件：负荷曲线、申报曲线、按价格分段的报价、储能充放电计划。
- 用户要查以前的申报记录（申报日志）。

## 需要的输入
- 曲线文件（CSV 或 Excel）的路径。
- 本市场的约束数值：申报电量的上下限（兆瓦）、相邻两点允许的爬坡（兆瓦）、申报步长（兆瓦）；报价的价格上下限（元/兆瓦时）；储能的容量（兆瓦时）、功率（兆瓦）、SOC 范围、效率和初始 SOC。这些先问用户，或用 `bailu handbook` 带省份名查本省规则（如〈山东省现货的申报与出清时间〉〈山西省现货的申报价格与出清限价〉），不要自己设。

## 步骤
1. 先运行 `bailu check <曲线文件>`：时间点是否齐全、有没有重复或乱序、数值是不是都读得出来。有「错误」先告诉用户。
2. 运行 `bailu curve <曲线文件> …`，把拿得到的约束都作为选项给出：
   - 按时间的曲线（负荷、出力、电量）：`--min --max --ramp --step`。
   - 报价曲线（价格列和电量列）：`--price-min --price-max`，售电加 `--side sell`。
   - 储能充放电曲线（一列充电为正放电为负，或充电、放电各一列）：`--capacity` 必给，`--power --soc-min --soc-max --efficiency --initial` 按需。
3. 逐项读结果。「不通过」的每一处都告诉用户：哪个检查项、在哪个位置、数值是多少、超了多少。「未检查」的项目说明缺哪个数值，向用户要了再跑。全部通过才说可以申报。
4. 申报电量已知、本省的允许偏差范围和考核标准也已知时，运行 `bailu calc pre_declaration --message "<用户原话>"`，看申报量会不会被考核。
5. 用户确认申报后记入台账：`bailu ledger add 申报 日期=<交易日> 市场=<日前/实时/中长期> 方向=<购电/售电> 电量=<兆瓦时> 价格=<元/兆瓦时> 曲线=<曲线文件> 备注="<一句话>"`。
6. 查以前的申报：`bailu ledger list 申报 [from=日期] [to=日期]`。

## 输出格式
- 第一句：结论（可以申报，或有几项不通过）。
- 不通过的项逐条列出：检查项、位置、说明。命令输出的表格原样放进回答。
- 最后一句：记入台账的内容，或还没有记录（用户还没确认申报）。

## 常见错误与提醒
- 约束数值只能来自用户或手册，不要替用户决定上下限和步长。
- 储能曲线必须有时间列（时刻、时段或日期时间），否则算不出每个时段的电量。
- 没给 `--initial` 时，结果是「能让全程合规的初始 SOC 区间」，不是检查结论，要照原样告诉用户。
- 省级规则经常修订，以用户提供的现行文件为准（〈规则的时效〉）；手册里的数值注明了施行时间。
- 台账只追加。发现以前记错了，告诉用户由其处理，不要改写已有的行。
- 「可以申报」只表示满足给出的约束；用户给的约束不全时，在结论里说明还缺哪些。
