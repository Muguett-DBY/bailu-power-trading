# 交易数据配置与验收

1. 先确定地区、市场品种、节点或主体、交割范围和用途。数据可以来自项目里已有文件或用户选定的公开只读源。公开源保存可访问的发布页、下载时刻、文件原名和涵盖范围，上传或交易平台操作由用户负责。
2. 在项目中保留原件。需要跨期复用、复算或追溯时，按 [数据清单格式](references/source-manifest.md) 登记 `bailu-workspace/data/sources.json`。区分交割时段、数据可用时刻和下载时刻。未确认发布时间时保留未知值。为每个修订快照使用独立编号，避免覆盖旧版本。
3. 读取副本并对齐时间与单位。说明时间戳是区间起点、终点还是时段编号，按源定义处理跨午夜。先按地区、市场、节点和交割时段分组，再合并同口径数据。明确用 MW 还是 MWh，或用元/kWh 还是元/MWh。缺数保留为空，按可用时刻选可追溯的修订，无法判定的冲突行进入异常表。不同粒度合并时按时间长度或场景指标需要的权重汇总，同时保留缺口与原件位置。
4. 报告输入版本、覆盖期、行数、缺口、重复、异常时段、单位换算和其它未决口径。批量统计和表格证据按 `price-risk-check` 与 `office-workflow`，进预测时按 `market-forecasting`，进草稿时按 `declaration-checklist`。

已知可用时刻时可用清单工具生成文件 SHA-256 和使用资格。它检查本地文件，公开 URL 在清单里供追溯。
