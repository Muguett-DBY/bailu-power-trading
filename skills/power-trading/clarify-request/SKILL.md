# 简短确认需求

1. 先查用户已经说过的话和项目里能直接找到的事实，必要时看相关项目记忆。常规、低风险且容易调整的选择直接采用合理默认，需要时说明假设。缺少会影响交易结论的金额、单位、地区、账期、适用规则或证据时，先确认关键事实。
2. 优先只问影响最大的一件事。最多同问两件互不依赖的事。适合选择时给两到三个互斥选项，推荐项放在首位，用一句话交代各自会改变什么。需要真实值时直接问那个值。推荐项可以是交付方式或核验路径，交易数字和政策适用性依靠证据。
3. 有选项时优先用宿主已开放的原生提问界面，例如项目给 Pi 装入的 `bailu_ask_user`、Codex 的 `request_user_input` 或 Claude Code 的 `AskUserQuestion`。工具不可用时在对话中简短问一次。用户取消或暂不回答时先保留选择，继续能独立做的部分。权限请求走宿主批准流程。
4. 等待答案时继续能独立完成的工作。依赖答案的计算或交付先等确认，收到后按选择继续。已回答的问题直接沿用，建议项只有在用户选择后才视为其决定。

多份同结构台账都已收到，用户只说「整理成 Excel」时，可以问「这个工作簿主要用于汇总筛选，还是分地区审阅？」有交互选项时，把「合并总表（推荐）」和「各地区分表」分别说明为统一筛选和独立审阅两种交付。
