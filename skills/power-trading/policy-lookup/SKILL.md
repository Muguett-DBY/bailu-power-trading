# 政策条款查询

## 适用场景
- 用户问规则内容、限价、时间节点、办理时限、某句话是第几条。
- 用户问「我们省」「本省」的规定。

## 需要的输入
- 省份、问的事项、时间（规则会更新）。
- 缺省份而问题涉及省级规定时，先问省份，不给具体数字（〈回答交易问题前的确认〉）。

## 步骤
1. 判断层级：
   - 国家层面：概念的官方定义，以及国家规则已经统一规定的内容（结算方式、结算流程与时限、市场注册、信息披露、供电营业规则、分时电价机制的原则要求、政府性基金及附加的项目等）。
   - 省级：用户点了省份名或说「本省」，或问报价限价、结算参考点、申报和出清时刻、偏差处理（〈省级规则的作用〉）、偏差考核比例（〈偏差电量〉）、分时时段和浮动比例（〈分时电价：峰、平、谷与尖峰〉）、本省输配电价水平（〈输配电价的监管周期与核定办法〉）、基本电费变更细则（〈基本电费计费方式的变更时限〉）。
2. 国家层面：运行 `bailu handbook`，参数保留专有名词和时间，一次最多写两个主题名。
3. 省级层面：运行 `bailu docs <政策文件夹> "<省份名> <事项的专有名词>"`（第一个参数是用户放本省文件的文件夹或文件，最后一个是问题）。用户给了政策文件，或指明了放政策文件的文件夹时，一定先用 `bailu docs <那个文件> "<省份名> <事项名>"` 查它。
4. 核对 `bailu docs` 的结果：
   - 有条款（每段以【文件名 第几页 第几条】开头）：按原文回答，写明文件名和条款编号，并说明依据是项目文件夹里的哪份文件或用户附上的哪份文件，以它为准。
   - 「没有找到相关内容」，并附「项目文件夹里的…份文件中没有找到相关条款」：告诉用户这些文件里没有这条规定，请用户把本省现行文件放进项目文件夹或直接附上。可以再运行 `bailu handbook` 给出国家层面的规定，并说明省级的具体规定以本省现行文件为准。
   - 说明里有「无法读取（可能是扫描件）」，或结果以「无法读取文件」开头：告诉用户哪份文件读不了，请换成文字版。
5. 几份文件说法不一致：命令结果里能看出新旧（日期、文号、废止说明）的按新的；看不出的，请用户确认哪份是现行文件，不要自己选。
6. 用户问的是文件里某句话是第几条：以结果段首的条款编号回答，直接说是第几条。
7. 结果里没有要找的主题：把主题名原样作为参数再查一次 `bailu handbook`；还没有就说明手册缺这部分。

## 输出格式
- 第一句：结论（条款怎么规定）。
- 第二句：依据，写文件名和条款编号，都照命令结果的写法，命令写简称就写简称，不补文号、不换全称。
- 第三句：适用范围。国家规定后提醒「各省的具体规定以本省文件为准」；省级规定后写明以哪份文件为准。

## 常见错误与提醒
- 数字、日期、条款编号只能来自命令结果或用户的话；查不到就说查不到，并说明缺哪份文件。
- 不把征求意见稿说成已执行。涉及现货规则、售电公司、输配电价时，先看时效：〈规则的时效〉〈售电公司管理办法的时效〉〈输配电价的监管周期与核定办法〉。
- 同一个命令不重复检索同样的内容；结果够用就开始回答。
- 不评价规定合理与否，不给交易建议。
