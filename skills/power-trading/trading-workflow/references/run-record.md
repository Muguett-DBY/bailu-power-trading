# 交易任务运行档案

用每个方案唯一的 `run_id`，在项目的 `bailu-workspace/runs/<run_id>/` 建目录。把文件路径写成项目内相对路径，用时间戳记录状态变化。一个任务反复修订时保留版本链。

| 字段 | 内容 |
| --- | --- |
| 任务与时间 | 地区、市场、主体、节点、交割日期、截止时间和时区 |
| 数据依据 | 文件和部位、数据清单 ID、可用时间、文件 SHA-256（需要复算时）、规则文号、条款和生效日期 |
| 比较口径 | 对照方案、备选方案、共同约束、价格及偏差情景、已知和待核实事项 |
| 计算记录 | 使用的技能或脚本、参数、运算范围、输出文件、复算说明 |
| 草稿状态 | 草稿版本、复核结论、待补项、人工确认与时间。已申报、已成交状态来自实际业务回执或用户确认 |
| 实际结果 | 计量、成交、结算与对应台账位置。结果缺失时保留待追踪项 |
| 差异与反馈 | 对照预测、假设、规则或数据质量拆解差异，写明证据、修订内容和下一次验证方法 |

建议随档案保存 `inputs.json`、`comparison.csv`、`draft-vN` 或 `review.md` 等实际交付物。简单任务可只交付所需文件。不要在档案里保存账户口令、接口密钥或私密会话全文。
