# 电力交易任务编排

确认地区、主体、产品、交割日、截止时间、授权范围和交付物。只执行本轮需要的步骤，缺少影响结果的字段按 `clarify-request` 优先确认。涉及多场景时按地区、品种和生效规则分开跑，最后按可比较口径汇总。

| 环节 | 动作与交付 |
| --- | --- |
| 数据与规则 | 用 `market-data-intake` 验收数据，按 `policy-lookup` 确认发布机关、条款、适用时段及版本，记录规则与输入证据 |
| 基线与备选 | 先定义当前方案或全实时的对照。需要时用 `market-forecasting` 和 `analysis/backtest.py`；收益按结算、零售或储能专用技能算清各项，并列可比较的备选 |
| 风险校验 | 用 `position-monitoring` 确认敞口、数据时效和风险限额，逐项列出结算假设及相反情景 |
| 起草与复核 | 用 `declaration-checklist` 校验量价、步长、曲线和设备约束。生成明确标注「待人工确认」的表或草稿，列出待决条款、截止前核对项和人工复核入口 |
| 档案与反馈 | 只在用户确认实际申报或成交后用 `trading-ledger` 记账；事后用 `trading-review` 与原预测、草稿比较，记录差异、修正事项和依据 |

复杂任务按 [运行档案模板](references/run-record.md) 在项目的 `bailu-workspace/runs/` 保存决策记录、草稿版本、输入与实际结果。记录可复算的理由、假设、人工确认与状态变化。实际申报由用户或有权限的业务人员完成。业务口径变更要留版本，确认后才按 `project-memory` 写入可复用的项目偏好或纠正。

交付时先报当前阶段、下一步及阻塞项，再给关键数字、风险、引用位置和结果路径。分析结果和拟采取的动作分别呈现。
