# 交易类计算器实现规格

写于 2026-11-26。供 Go 后端实现 9 个确定性计算器使用。模型只做意图标注和复述，不参与任何计算；单位、数值读取、缺参追问和输出格式沿用 `power_calc.go`、`power_nlu.go`、`power_flow.go` 的现有约定。

全文用三种标注：

- 【官方】有官方原文的逐字引文，出处编号见附录 A。
- 【口径】行业经验做法，或由官方条文推出的算式，没有逐字的官方原文。输出时写成「测算口径」，不得写成「规定」。
- 【未找到官方原文，不可作为事实输出】只能由用户提供，程序不得内置成事实。

测试用例里的电价、成本，除注明取自 1077号附件 1 的以外，都是演示用的假设值。期望值都是逐步手算的，再用独立的算术演算复核过一遍。

|---|---|---|---|
| 1 | 基本电费 | 105%、加一倍、40% 下限、多路进线累加、变更时限、按日折算、减容暂停、各省电价 | 105% 以内的计费基数、核定值上限、九折在第四监管周期是否延续 |

## 0. 公共约定

### 0.1 单位

沿用 `power_calc.go` 文件头的约定：电量以千瓦时、价格以元/千瓦时、比例以小数存储。本规格新增几类量。

| 量 | 内部单位 | 读取与换算 |
|---|---|---|
| 电量 | kWh | 现有 `parseEnergy`：兆瓦时 ×1000，万 ×10000 |
| 电能量价格 | 元/kWh | 现有 `parsePrice`：元/兆瓦时 ÷1000，厘 ÷1000 |
| 比例 | 小数 | 现有 `parseRate`：`5%` 读成 0.05；不带百分号且大于 1 的数按百分数读 |
| 容量 | kVA | 新增 `parseCapacity` |
| 需量、功率 | kW | 新增 `parsePower`：兆瓦 ×1000，万千瓦 ×10000 |
| 无功电量 | kvarh | 新增 `parseReactive`：乏时 ÷1000 |
| 容量电价 | 元/(kVA·月) | 新增 `parseCapacityPrice` |
| 需量电价 | 元/(kW·月) | 新增 `parseDemandPrice` |
| 金额 | 元 | 新增 `parseMoney`：万元 ×10000 |
| 天数、循环次数 | 整数 | 现有 `parseBareNumber` |

### 0.2 舍入

- 全程用 `decimal.Decimal` 精确计算。除法沿用库的默认精度，中间值不按展示位数舍入。
- 展示时四舍五入：金额 2 位小数；电价最多 6 位（现有 `formatPrice`）；比例按百分数 2 位（现有 `formatRate`）；电量、容量、需量、功率保留 2 位并去掉尾零。金额保留两位小数与 976号第十二条对市场结算电费的要求一致（A7）。
- 合计由未舍入的值算出后再舍入。差异桥另设「舍入尾差」一行，见 8.3。
- 测试用例的期望值写到展示位数；断言时对未舍入的结果调用 `Round(n)` 再比较。

### 0.3 新增读取器

仿照 `power_calc.go` 的写法。`NUM` 代表现有的数字段 `\d{1,3}(?:[,，]\d{3})+|\d+`（后可接小数）。

| 读取器 | 正则 | 换算 |
|---|---|---|
| `parseCapacity` | `(?i)^\s*NUM\s*(万)?\s*(千伏安\|kva)\s*$` | 有「万」时 ×10000 |
| `parsePower` | `(?i)^\s*NUM\s*(万)?\s*(千瓦\|kw\|兆瓦\|mw)\s*$` | 兆瓦 ×1000；万千瓦 ×10000 |
| `parseReactive` | `(?i)^\s*NUM\s*(万)?\s*(千乏时\|kvarh\|乏时)\s*$` | 乏时 ÷1000；有「万」时 ×10000 |
| `parseCapacityPrice` | `(?i)^\s*NUM\s*(元\|圆)?\s*/\s*(千伏安\|kva)\s*(?:[·•*/]\s*)?(?:每)?(?:个)?月\s*$` | 无 |
| `parseDemandPrice` | `(?i)^\s*NUM\s*(元\|圆)?\s*/\s*(千瓦\|kw)\s*(?:[·•*/]\s*)?(?:每)?(?:个)?月\s*$` | 无 |
| `parseMoney` | `^\s*NUM\s*(万)?\s*(元\|圆)\s*$` | 有「万」时 ×10000 |

表格里的 `\|` 是转义的竖线，写进 Go 代码时就是普通的 `|`。

`scan` 里的扫描顺序改为：日期与时刻 → 电能量价格 `qPrice` → 电量 `qEnergy` → 容量电价、需量电价 → 容量、功率、无功电量 → 金额 `qYuan`（扩展到支持「万元」）→ 百分数 → 其余照旧。理由有两条。`38元/千瓦·月` 不匹配 `qPrice`，却会被现有的 `qYuan` 抢先读成 38 元/千瓦时，所以两个电价读取器必须排在 `qYuan` 之前。「千瓦时」必须先于「千瓦」被占用。

没写单位的数字，由紧邻的词决定角色，再按这个角色的默认单位读取，与现有的 `bareEnergyRole`、`readBarePrice` 做法相同。各角色的默认单位写在各计算器的输入表下面。

三处要特别处理的词：

- 「申报」现在把电量归到 `contract_energy`。申报前校验里申报量和合约量是两个量，要单列 `declared_energy`，只在该意图下生效。
- 「电费」既可能是基本电费，也可能是现货结算。「基本电费」「需量电费」「容需量」归基本电费，「电费怎么算」仍归现货结算。
- 「储能」归储能计算器，「削峰」「移峰」「蓄冷」「蓄热」归负荷平移。同时出现时储能优先。

### 0.5 数据源

`research/data/transmission-tariffs.json` 是 1077号附件 1《省级电网输配电价表》的结构化数据，自 2026-08-01 起执行，含各省的 `输配电价-需量电价`（元/千瓦·月）和 `输配电价-容量电价`（元/千伏安·月）。基本电费计算器在用户报了省份和电压等级、但没有直接给电价时从这里取数，并在输出里写明取自哪张表。Go 代码目前还没有读取这个文件的函数，需要新增。用户直接给的电价优先。

## 1. 基本电费

### 1.1 用途与适用对象

两部制工商业用户当月基本电费的计算，按变压器容量和按最大需量两种计费方式的比选，含合同最大需量超 105% 的加倍、40% 核定下限、按日折算、减容暂停期间的计收。用电容量在 315 千伏安及以上的用户执行两部制，100 千伏安以上至 315 千伏安之间的可以选择（A3 第三条）。使用者是用电企业的电气或能源管理人员、售电公司的客户经理。

### 1.2 输入参数

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `capacity` | 受电变压器容量，多路进线逐路给 | kVA | 是 | 变压器容量 630 千伏安；630kVA；两台 800 千伏安（相加得 1600） |
| `motor` | 不通过受电变压器的高压电动机容量 | kVA | 否，缺省 0 | 高压电动机 200 千伏安 |
| `capacity_price` | 容量电价 | 元/(kVA·月) | 按容量时必填 | 容量电价 33 元/千伏安·月；每千伏安每月 33 元；北京 10 千伏两部制（从数据表取） |
| `demand_price` | 需量电价 | 元/(kW·月) | 按需量时必填 | 需量电价 52 元/千瓦·月；52 元/千瓦/月 |
| `mode` | 计费方式 | 容量或需量 | 否 | 按容量；按最大需量。两种方式的参数都给齐时两算并比选 |
| `declared` | 合同最大需量核定值，逐路 | kW | 按需量时必填 | 合同最大需量 1096 千瓦；核定需量 1096 |
| `actual` | 实际最大需量，逐路 | kW | 按需量时必填 | 实际最大需量 1150 千瓦；最大需量 1150 |
| `demand_factor` | 需量电价执行比例 | 小数 | 否，缺省 1 | 需量电价打九折；需量电价按 90% 执行 |
| `month_energy` | 当月全部计量点的总用电量 | kWh | 否 | 当月用电 42 万千瓦时 |
| `days` | 实用天数 | 天 | 折算时必填 | 8 月新装，用了 10 天 |
| `calendar_days` | 当月日历天数 | 天 | 折算时必填；给了月份就按月份定（2 月 28 天，闰年 29 天） | 当月 31 天 |
| `segments` | 当月容量变更的分段，每段含天数和变更后的容量 | 天、kVA | 有减容、增容、恢复时必填 | 9 月 16 日起减容 630 千伏安，减容后 970 千伏安 |
| `reduction_days` | 实际减容天数 | 天 | 判断减容是否满十五日时必填 | 减了 8 天就恢复了 |

没写单位时的默认：`capacity`、`motor` 按千伏安，`declared`、`actual` 按千瓦。

必须拒绝的输入：容量不大于 0；按需量但缺核定值或实际需量；要算临界需量但需量电价为 0；折算时某段天数大于日历天数，或各段天数之和大于日历天数；日历天数不在 28 到 31 之间。

### 1.3 计算步骤

**第 1 步，下限。** 对每一路进线 j，容量 C_j = capacity_j + motor_j，核定下限 F_j = 0.4 × C_j。总容量 C 是各路 C_j 之和。千伏安和千瓦按数值相等对待，1583号没有给出换算系数。

**第 2 步，按容量。** 全月容量电费 = C × capacity_price。

备用变压器怎么取舍，由用户按自己的情形报 `capacity`，程序不判断备用状态。规则是：冷备用并经加封的不收，热备用或未经加封的照收，互为备用的按可能同时使用的容量之和的最大值计（A2 第八十七条）。

**第 3 步，按最大需量。** 逐路计算后累加：

```
D_j      = max(declared_j, F_j)
over_j   = max(actual_j − 1.05 × D_j, 0)
计费需量  B_j = D_j + 2 × over_j
全月需量电费 = demand_price × demand_factor × Σ B_j
```

| 条件 | 结果 | 依据 |
|---|---|---|
| actual_j ≤ 1.05 × D_j | 不加倍，按核定值计 | 「未超过合同确定值105%的，按合同确定值收取」（A1） |
| actual_j > 1.05 × D_j | 超出部分的基本电费加一倍，即该部分按 2 倍计 | 「超过105％部分的基本电费加一倍收取」（A1） |
| declared_j < F_j | 核定值按 F_j 计，再判断是否超 105% | 「按容量总和的40%核定合同最大需量」（A1） |
| actual_j 恰好等于 1.05 × D_j | 属于未超过，不加倍 | 1583号写的是「超过」。《供电营业规则》第一百零九条把「超过」界定为不包括本数，这里按同样的读法处理，属口径（A2） |

「超过 105% 部分加一倍」的算式，1583号没有写成公式。上面的算式沿用手册〈合同最大需量超105%的加收规则〉的读法：105% 以内按合同值计，超出部分乘 2。这是【口径】，见 1.7。

**第 4 步，分段与按日折算。** 把当月分成若干段，每段内容量和核定值不变。先按第 2、3 步算出每一段按全月计的电费 f_i，再折算：

```
当月基本电费 = Σ f_i × d_i ÷ n
```

d_i 是该段天数，n 是当月日历天数。只有一段且没给天数时，直接取全月电费。

| 情形 | 分段 | 依据 |
|---|---|---|
| 新装，实用 d 天 | 一段，d_1 = d | 「应当按照实用天数计算，每日按照全月容（需）量电费除以当月日历天数收取」（A2 第八十六条） |
| 当月 d 日增容 | 两段：d − 1 天按原容量，n − d + 1 天按新容量 | 同上，增容当月按实用天数 |
| 当月 d 日减容，持续到月底 | 两段：d − 1 天按减容前容量，n − d + 1 天按减容后容量 | 「自减容之日起，按照减容后的容量执行相应电价政策」（A2 第二十五条）；「自设备加封之日起，减容（暂停）部分免收基本电费」（A1） |
| 当月 d 日减容恢复 | 两段：d − 1 天按减容后容量，n − d + 1 天按恢复后容量 | 「容（需）量电费从减容恢复之日起按照恢复后的容（需）量计收」（A2 第二十五条） |
| 实际减容天数少于 15 天 | 不分段，整月按减容前容量 | 「实际减容时长少于十五日的，停用期间容（需）量电费正常收取」（A2 第二十五条） |
| 事故停电、检修停电、有序用电 | 不折算 | 「不扣减容（需）量电费」（A2 第八十六条） |

日用电不足 24 小时的按一天计，所以 `days` 只取整数。加封之日算进减容后的那一段，这是本规格的约定，原文没有写明起算日，见 1.7。表里各种情形的分段算式，是把「应当按照实用天数计算」和「自减容之日起，按照减容后的容量执行相应电价政策」这样的句子合起来得到的。增容和恢复两种情形，原文只说了按实用天数计算，没有写出公式。这些都属【口径】。

按需量计费的月份发生减容时，每一段用各自的核定值和实际需量算 f_i。把第八十六条用于需量方式的这一步是推导，属【口径】。减容后仍按最大需量计费的，核定值要按减容后的总容量申报（A1 第二条第（三）项），这时第 1 步的 F_j 相应变小。

**第 5 步，比选与盈亏平衡。** 两种方式的当月电费都算出来后比较。另外给出两个临界需量和事后最优核定值，用来解释结论：

```
临界需量（保守口径）A_c = C × capacity_price ÷ (demand_price × demand_factor)
临界需量（贴线口径）A_t = 1.05 × A_c
事后最优核定值     D*  = min( ceil_step( max(actual ÷ 1.05, F) ), C )
```

`step` 是核定值的申报粒度，缺省 1 千瓦。

| 实际最大需量 A | 结论 |
|---|---|
| A < A_c | 按需量更省；核定值不低于实际需量时也省 |
| A_c ≤ A < A_t | 核定值贴近实际需量的 105% 时按需量更省；核定值不低于实际需量时按容量更省 |
| A ≥ A_t | 按容量更省 |

A_c 是手册〈比选容量与需量计费的经验口径〉里的分界点，A_t 是把核定值压到刚好不触发加倍时的分界点。两者都是【口径】。D* 用的是事后的实际峰值，只是费用的下界，实际申报要用负荷预测的峰值。

**第 6 步，九折，只提示，不自动套用。** 用户给了 `month_energy` 时，算每千伏安用电量 = month_energy ÷ capacity，并在输出里说明：526号第三条规定达到 260 千瓦时及以上时当月需量电价按 90% 执行。是否按 0.9 计取决于用户给的 `demand_factor`，原因见 1.7。

### 1.7 地方差异与不确定

- 「超过 105% 部分加一倍」的算式是沿用手册的读法，属【口径】。105% 以内按合同值计，还是按 105% 乘核定值计，各省细则和电网企业的计费算式没有逐一核对。两种读法相差 0.05 × 核定值 × 需量电价。
- 核定值的上限：1583号没有规定。把总容量当作上限是口径。
- 多路进线时 40% 下限按各路分别适用，是从「各路进线分别计算最大需量」推导的口径。
- 九折的 260 千瓦时和 90% 出自 526号第三条。1077号的正文没有提到九折，也没有写明 526号其他条款的去留。第四监管周期是否延续，未找到官方原文，不可作为事实输出，所以程序不自动套用。
- 两部制的容量界限出自 526号第三条，是第三监管周期的文件。1077号的正文没有重申这个界限，附件里是否另有说明没有核对。
- 1583号的现行有效性没有做系统核对。《供电营业规则》2024 年版第八十七条仍写「计收方式按照相关电价政策规定执行」。
- 减容十五日的起算日、需量方式下变更当月怎样按日折算，原文没有细化。
- 「按实际最大需量」计费的第三种方式没有读到国家文件依据，不实现。
- 数据表里各省的列名不完全一致，例如辽宁的「10（20）千伏及以下」、深圳按用电类别分档。取数时按数据集的原样字段匹配。

## 2. 功率因数调整电费

### 2.1 用途与适用对象

执行功率因数考核的用户。由当月有功、无功电量求月平均功率因数，对照三档标准判断是否达标，按用户提供的增减比例算力调电费，并估算补到标准还差多少无功电量。

### 2.2 输入参数

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `active` | 当月有功电量 | kWh | 是 | 有功电量 30 万千瓦时 |
| `reactive` | 当月无功电量 | kvarh | 是 | 无功电量 20 万千乏时；200000 kvarh |
| `standard` | 功率因数标准 | 小数 | 是 | 功率因数标准 0.9；按 0.85 考核 |
| `rate` | 取整后的功率因数对应的调整比例，正数增收、负数减收 | 小数 | 算金额时必填 | 0.83 对应增收 3.5%；减收 0.75% |
| `table` | 对照表，每行是「功率因数下限、比例」 | 无 | 否 | 0.9 及以上 0；0.85 增收 2%；再低增收 5% |
| `base` | 力调电费的基数 | 元 | 否 | 基数 19.5 万元 |
| `target` | 补偿要达到的功率因数 | 小数 | 否，缺省等于 `standard` | 补到 0.95 |

`standard` 不给就追问，追问时列出三档标准让用户对号。不替用户按电压或容量去猜。

必须拒绝的输入：有功电量不大于 0；无功电量为负；标准不在 0 到 1 之间；比例小于 −1；给了表但没有一行适用。

### 2.3 计算步骤

1. 未取整的功率因数 c = active ÷ √(active² + reactive²)。
2. 取整 c2 = Round(c, 2)，四舍五入。
3. 判定：c2 ≥ standard 为达标。标准是 0.90、0.85 时原文是「以上」，含本数。
4. 定比例 r。给了 `table` 就查表，取下限不高于 c2 的最低一行；否则用 `rate`。用户报比例时如果同时写了功率因数，且与算得的 c2 不同，提示两者不一致，请用户确认后再算金额。
5. 力调电费 = base × r。正数是加收，负数是减收。
6. 补偿无功电量。未取整的 c 小于 `target` 时，ΔQ = reactive − active × tan φ_t，其中 tan φ_t = √(1 ÷ target² − 1)；否则 ΔQ = 0。tan φ_t 对 0.90、0.85、0.80 分别是 0.4843221048、0.6197443384、0.75，用 `decimal` 的平方根算。

| 条件 | 结论 |
|---|---|
| c2 ≥ standard，c ≥ standard | 达标，ΔQ = 0 |
| c2 ≥ standard，c < standard | 取整后达标。ΔQ 是把功率因数精确补到标准所需的量，输出时同时给未取整值 |
| c2 < standard | 未达标，需要补偿 ΔQ |

tan φ 可以直接用电量相除得到，所以第 6 步不需要反三角函数。ΔQ 的含义是：有功电量不变，把无功电量减到 active × tan φ_t，功率因数就恰好等于 `target`。这是【口径】。《供电营业规则》考核的是「电网高峰负荷时的功率因数」（A2 第四十五条），按月电量折算只是近似的算法。补偿容量还要拿高峰时刻的无功功率来校核，本计算器不算。

### 2.5 调整率表找不到官方原文时的替代做法

本轮做了 4 次定向检索，其中 3 次限定 gov.cn 域名，并用了「发改委」「转发」「功率因数调整电费表」等词，都没有出现政府网站上带对照表的 215号原文。搜到的只有企业网站和文库的转载。上一轮研究记录过两个政府网页：鄂州市华容区政府的网页正文是图片，柳州市发改委的 PDF 无法读取。本轮没有找到可读的文字版。因此：

1. 不内置任何一张调整率表，不从非政府网站抄表。
2. 分两步算。第一步只算功率因数、是否达标、要补多少无功电量，这些不需要比例。第二步请用户报出本省对照表中该功率因数对应的增减比例，再算金额。追问的写法：「请查本省的功率因数调整电费对照表，告诉我 0.83 对应的增减比例，例如增收 3.5%。」
3. 用户可以一次粘贴多行对照表，程序在本次会话内按表查找，输出注明「比例来自你提供的对照表」。
4. 用户问「0.88 要加收百分之几」时，回答没有收录官方对照表，请其提供，不给数字。

- 调整率表、基数口径、取整规则三项都没有读到官方原文。取整规则会影响临界用户的结论，用例 2-5 就是一例。

- 现货用户、市场化交易用户的力调电费怎样算，国家文件没有规定。
- 一条待核的线索：检索摘要称，河北省发展改革委 2023 年 6 月 20 日《关于继续执行阶段性降低中小微企业用电成本的通知》规定，上网环节线损费用和系统运行费用不参与功率因数调整电费计算。这是摘要的转述，不是原文；本轮没有读到这份通知。基数口径有省级规定这一点值得后续核对，这条线索本身不可作为事实输出。
- 国家发展改革委在两份答复里都表示要适时修改 1983 年的办法（A5），修改后的标准要重新核对。

## 3. 售电公司履约保障额度

### 3.1 用途与适用对象

售电公司参与批发或零售市场交易前，计算应向电力交易机构提交的履约保函或履约保险额度，已提交的够不够，差多少。使用者是售电公司的财务或交易人员。

### 3.2 输入参数

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `wholesale12` | 过去 12 个月批发市场交易总电量 | kWh | 是 | 过去 12 个月批发交易电量 360 万千瓦时 |
| `recent_max` | 过去 2 个月内批发、零售两个市场交易电量的大值 | kWh | 是。可以直接给，也可以由下一项求最大值 | 近两个月交易电量最大 60 万千瓦时 |
| `recent_volumes` | 近两个月各市场的月交易电量 | kWh | 否 | 批发 120 万、100 万千瓦时，零售 115 万、98 万千瓦时 |
| `rate12` | 批发项的标准 | 元/kWh | 否，缺省 0.008 | 不低于 0.8 分/千瓦时；本省 1 分 |
| `rate2` | 近期项的标准 | 元/kWh | 否，缺省 0.05 | 不低于 5 分/千瓦时 |
| `submitted` | 已提交的履约保函、保险金额 | 元 | 否，缺省 0 | 已提交保函 20 万元 |

「分/千瓦时」换算成元/千瓦时要除以 100。

必须拒绝的输入：电量为负；两项标准为负；`recent_volumes` 的个数多于 4。

### 3.3 计算步骤

```
recent_max = max(recent_volumes)        给了 recent_volumes 时
G1 = wholesale12 × rate12
G2 = recent_max × rate2
应缴额度   G  = max(G1, G2)
补缴缺口      = max(G − submitted, 0)
可申请退还    = max(submitted − G, 0)
```

| 条件 | 结论 |
|---|---|
| G1 > G2 | 按批发项，即过去 12 个月那一项 |
| G2 > G1 | 按近期项，即近 2 个月那一项 |
| G1 = G2 | 两项相同，额度相等 |
| submitted < G | 有缺口，接到通知后 3 个工作日内补缴 |
| submitted > G | 多缴的部分可以向电力交易机构申请退还（A6 第二十五条） |

`recent_volumes` 有则取其中最大值，没有就用 `recent_max`。「近 2 个月大值」按「两个月内各市场月电量的最大值」实现，是本规格的读法，见 3.7。

| 常数或规则 | 值 | 性质 | 出处 |
|---|---|---|---|
| 批发项标准 | 不低于 0.8 分/千瓦时，即 0.008 元/千瓦时 | 官方，是国家标准的下限 | A6 第二十四条 |
| 近期项标准 | 不低于 5 分/千瓦时，即 0.05 元/千瓦时 | 官方，是国家标准的下限 | A6 第二十四条 |
| 取大 | 两个额度中的最大值 | 官方 | A6 第二十四条 |

| 多省开展业务 | 分别提交 | 官方 | A6 第二十四条第（一）项 |

## 4. 零售套餐比价

### 4.1 用途与适用对象

电力用户或其售电公司在签零售套餐前，在同一条用电曲线下比较固定价、分时价、市场联动价三种套餐的电能量费用，并求市场联动与固定价持平时的市场价变动幅度。

### 4.2 输入参数

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `bands` | 各时段的用电量 | kWh | 是 | 峰 10 万、平 15 万、谷 5 万千瓦时 |
| `fixed_price` | 固定套餐的价格 | 元/kWh | 否，比较固定价时必填 | 固定价 0.65 |
| `tou_prices` | 分时套餐各时段的价格 | 元/kWh | 否，比较分时价时必填 | 分时价峰 0.95、平 0.62、谷 0.36 |
| `pass_through` | 联动的传导系数 α | 小数 | 联动套餐必填 | 传导系数 1；按市场价的 80% 传导 |
| `adder` | 联动的加价 a | 元/kWh | 联动套餐必填，可以为 0 | 加价 3 分 |
| `cap`、`floor` | 联动价格的上限、下限 | 元/kWh | 否 | 上限 0.9，下限 0.45 |
| `spot` | 各时段的基准市场价 S_t | 元/kWh | 联动套餐必填 | 市场价峰 0.85、平 0.55、谷 0.25 |
| `scenarios` | 市场价相对基准的变动比例 x | 小数 | 否；不给时用 −0.2、0、0.2 三个演示情景 | 市场价涨 20%、跌 20% |

至少要有两种套餐的参数，否则没有可比的。三种套餐的时段划分必须一致。

必须拒绝的输入：时段电量为负；传导系数为负；下限大于上限；`scenarios` 小于 −1。

### 4.3 计算步骤

**费用。** t 遍历各时段，Q = Σ q_t。

```
固定价   C_f   = Σ q_t × fixed_price
分时价   C_tou = Σ q_t × tou_price_t
联动价格  p_t(x) = min( max(α × S_t × (1 + x) + a, floor), cap )
联动价   C_l(x) = Σ q_t × p_t(x)
度电均价 = 费用 ÷ Q
```

没有给 `floor` 或 `cap` 的，相应的一侧不截。

**临界变动幅度 x*。** 联动的价格是分段线性的，所以 C_l(x) 也是分段线性的，并且随 x 单调不减。求 C_l(x*) = C_f 的步骤：

1. 对每个 α × S_t 大于 0 的时段算两个拐点：触上限的 x_cap,t = (cap − a) ÷ (α S_t) − 1，触下限的 x_floor,t = (floor − a) ÷ (α S_t) − 1。把落在 −1 以上的拐点去重、升序排列，把 x ≥ −1 切成至多 2n + 1 段。
2. 每一段里，各时段处在「线性」「触上限」「触下限」三种状态之一，段内不变。所以

   ```
   C_l(x) = A_k × (1 + x) + B_k
   A_k = Σ(线性时段) q_t × α × S_t
   B_k = Σ(线性时段) q_t × a + Σ(触上限时段) q_t × cap + Σ(触下限时段) q_t × floor
   ```

3. 按下面的表定根。

| 条件 | 结论 |
|---|---|
| C_f < C_l(−1) | 联动在任何情景下都比固定价贵，x* 不存在 |
| C_f > C_l 的最大值 | 联动始终比固定价便宜，x* 不存在 |
| 落在某一段内，A_k > 0 | x* = (C_f − B_k) ÷ A_k − 1 |
| 落在某一段内，A_k = 0 | 整段都持平，取该段下端点作为 x*，并说明是一个区间 |

x ≥ −1 是因为市场价最多跌到零。

**同口径。** 三种套餐都只算电能量这一项。直接参与交易的用户侧用电价格由电能量价格、输配电价、上网环节线损费用、系统运行费用、政府性基金及附加构成（A8 第三十四条）。除电能量外的各项对三种套餐相同，比价后再同口径加回。

### 4.6 输出格式

套餐表：套餐、电能量费用（元）、度电均价（元/千瓦时）、与固定价的差额（元）。

情景表：市场价变动、联动各时段价格（注明触上限或触下限）、联动费用（元）、与固定价的差额（元）。

临界点单列一行：市场价相对基准上浮或下浮多少时，联动与固定价持平，并给出此时各时段的市场价 S_t × (1 + x*)。临界点不存在时，写明是联动始终更贵还是始终更便宜。

必须附带的提醒：

1. 只比了电能量费用。输配电价、上网环节线损费用、系统运行费用、政府性基金及附加和基本电费，各种套餐都要交，须同口径另加。
2. 市场价和情景由你提供，本计算不做价格预测。
3. 联动的公式和四个参数以零售合同为准。套餐的形式是国家文件没有规定的合同约定，这里用的是测算口径。

### 4.7 地方差异与不确定

- 零售套餐有哪些形式、联动公式怎样写，国家文件没有规定。各省的套餐和结算模式不同，本规格只支持「乘传导系数再加价，加上下限」这一种。别的形式，例如固定价差模式，等价于 α 取 1，可以换算后使用。
- 联动的是哪个市场价，分时现货价、月度加权价还是统一结算点价，由合同约定。程序只接受用户给的各时段基准价。
- 《电力零售市场基本规则》截至 2026 年 11 月 26 日未见正式印发。国家能源局在 2026 年 10 月 30 日的新闻发布会上表示即将出台，见研究稿 `research/handbook/market-system.md`。出台后要核对本节的口径。

## 5. 固定价套餐保本点

### 5.1 用途与适用对象

售电公司在签固定价零售套餐前，或在持有期间，算保本的现货价、价格安全垫和度电净利，回答「现货价涨到多少这张合同会亏」。使用者是售电公司的交易或财务人员。

### 5.2 输入参数

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `retail` | 零售固定价 P | 元/kWh | 是 | 零售价 0.65；卖给用户 0.65 元/度 |
| `forward_share` | 中长期电量占售电量的比例 c | 小数 | 是 | 中长期覆盖 80% |
| `forward_price` | 中长期合约价 L | 元/kWh | c 大于 0 时必填 | 中长期价 0.58 |
| `spot` | 现货加权价 S | 元/kWh | c 小于 1 时必填 | 现货加权 0.60 |
| `deviation_cost` | 度电偏差成本 D | 元/kWh | 否，缺省 0 | 偏差成本 5 厘 |
| `operating_cost` | 度电运营成本 O | 元/kWh | 否，缺省 0 | 运营成本 2 分 |
| `funding_cost` | 度电担保资金成本 F | 元/kWh | 否，缺省 0；可以由辅助算式得出 | 保函额度 3 万元，费率 1%，年电量 360 万千瓦时 |
| `energy` | 合同期内的售电量 Q | kWh | 算净利总额时必填 | 年电量 360 万千瓦时 |

必须拒绝的输入：零售价不大于 0；比例小于 0 或大于 1；比例等于 1 却要求保本现货价；比例小于 1 却没有现货价；辅助算式里售电量为 0。

### 5.3 计算步骤

```
加权采购价 W = c × L + (1 − c) × S
度电净利   m = P − W − D − O − F
净利总额     = m × Q
保本现货价  S* = (P − D − O − F − c × L) ÷ (1 − c)
安全垫       = S* ÷ S − 1
```

辅助算式，担保资金成本：F = 履约保障额度 × 保函费率 ÷ Q。履约保障额度按第 3 节计算。

| 条件 | 结论 |
|---|---|
| c = 1 | 没有现货敞口，保本现货价不适用，只报度电净利 P − L − D − O − F |
| S* > S | 当前现货价下盈利。安全垫为正，现货价还可以涨这么多 |
| S* = S | 持平 |
| S* < S | 当前现货价下已经亏损。安全垫为负，现货价要跌这么多才保本 |
| S = 0 | 安全垫无法计算，只报 S* |

下面这个恒等式可以用于测试断言：

```
m = (1 − c) × (S* − S)
```

「零售价减采购价」只是毛价差。偏差、运营、担保资金成本和坏账都扣掉才是净利。这是【口径】。坏账本计算器不计。

### 5.4 常数与参数表

| 项 | 性质 | 出处 |
|---|---|---|
| D、O、F、c、L、S | 没有官方默认值，全部由用户输入 | 无 |
| 保本现货价和安全垫的算式 | 口径，是成本构成的恒等式 | 无 |
| 售电公司的结算电费是零售市场与批发市场结算电费之差 | 官方，说明售电的盈利来自批零价差 | A7 第四十六条 |
| 履约保障额度的算法，用于辅助算式 | 官方 | A6 第二十四条 |

### 5.6 输出格式

第一张表：零售价、加权采购价、度电偏差成本、度电运营成本、度电担保资金成本、度电净利（元/千瓦时）、售电量（千瓦时）、净利（元）。

必须附带的提醒：

1. 「零售价减采购价」是毛价差，扣掉各项成本才是净利。
2. 安全垫没有统一的合理值，要多厚取决于合同剩余期限和价格波动。
3. 没有计坏账。
4. 中长期比例、价格和现货价都是你给的假设。这里把现货价当作全部未覆盖电量的同一个加权价，实际的分时结构会影响结果。

### 5.7 地方差异与不确定

- 偏差成本、运营成本、资金成本都没有官方默认值。
- 本计算器把现货价当作单一的加权价，不处理分时曲线。峰谷差大的时候，结果会偏离实际结算。
- 辅助服务分摊、不平衡资金等没有纳入。

## 6. 用户侧储能：削峰降低基本电费与峰谷套利

### 6.1 用途与适用对象

工商业用户评估用户侧储能：峰谷套利的年净收益、价差门槛和回收期；按最大需量计费的用户，储能削峰能省多少基本电费。计算分五步：每次循环、年度收益、门槛与回收期、需量影响，以及可选的最低峰值求解。

### 6.2 输入参数

套利部分：

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `power` | 额定功率 | kW | 是 | 500 千瓦 |
| `capacity` | 额定容量 | kWh | 是 | 1000 千瓦时；1 兆瓦时 |
| `efficiency` | 往返效率，交流侧 | 小数 | 是 | 往返效率 88%；效率 0.88 |
| `dod` | 放电深度 | 小数 | 否，缺省 1 | 放电深度 90% |
| `days` | 年可用天数 | 天 | 是 | 每年 330 天 |
| `cycles` | 每日循环次数 | 次 | 是 | 每天两充两放，即 2 次 |
| `charge_price` | 充电价 | 元/kWh | 是 | 谷段 0.30 元 |
| `discharge_price` | 放电价 | 元/kWh | 是 | 峰段 0.95 元 |
| `unit_investment` | 单位投资 | 元/kWh | 算净利时必填；也可以给总投资 | 单位造价 900 元/千瓦时；总投资 90 万元，除以容量 |
| `cycle_life` | 循环寿命 | 次 | 算净利时必填 | 循环寿命 6000 次 |
| `annual_oem` | 年运维费 | 元 | 否，缺省 0；可以给占投资的比例 | 年运维为投资的 1.5% |

需量部分：

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `load` | 逐时或逐时段的负荷 | kW | 算需量影响时必填 | 10 点 1150 千瓦，11 点 1180 千瓦……；或 CSV 的时间和负荷两列 |
| `charge_schedule`、`discharge_schedule` | 逐时的充电、放电功率 | kW | 同上 | 10 点到 14 点分别放 150、180、100、160、50 千瓦 |
| `lines`、`demand_price` | 同第 1 节 | 同第 1 节 | 同上 | 变压器容量 1600 千伏安，需量电价 40 |

没写单位时，功率默认千瓦，容量默认千瓦时。

必须拒绝的输入：功率或容量不大于 0；效率不大于 0 或大于 1；放电深度不大于 0 或大于 1；天数或循环次数不大于 0；充放电序列与负荷序列长度不一致；任一时刻的充电或放电功率超过额定功率。

### 6.3 计算步骤

**第 1 步，每次循环。**

```
放电量 E_out = capacity × dod
充电量 E_in  = E_out ÷ efficiency
每循环毛收益 g = E_out × discharge_price − E_in × charge_price
```

E_out 是交流侧交付的电量，E_in 是交流侧取用的电量，效率按交流侧的往返效率计。

**第 2 步，年度。**

```
年放电量 = days × cycles × E_out
年充电量 = days × cycles × E_in
年毛收益 = days × cycles × g
度电成本 c = unit_investment ÷ (cycle_life × dod) + annual_oem ÷ 年放电量
年成本   = 年放电量 × c
年净收益 = 年毛收益 − 年成本
```

度电成本的第一项是投资折合到每放电 1 千瓦时：总投资是 unit_investment × capacity，全寿命的放电量是 cycle_life × capacity × dod，两者相除。

**第 3 步，门槛与回收期。**

```
价差门槛   = charge_price × (1 ÷ efficiency − 1) + c
实际价差   = discharge_price − charge_price
简单回收期 = 投资 ÷ 年净收益
折合寿命   = cycle_life ÷ (days × cycles)
```

价差门槛的意思是：每放电 1 千瓦时，要多买 1 ÷ efficiency − 1 千瓦时的电，这部分按充电价计，再加上每千瓦时的度电成本。实际价差不低于门槛，每次循环才赚钱。

| 条件 | 结论 |
|---|---|
| 年净收益不大于 0 | 无法回收 |
| 回收期大于折合寿命 | 电池寿命内无法回收 |
| 其余 | 回收期如所算 |

**第 4 步，需量影响。** 只适用于按最大需量计费的用户。

```
削峰前最大需量 A_0 = max_t load_t
削峰后最大需量 A_1 = max_t (load_t + charge_t − discharge_t)
核定值 D*  = min( ceil_step( max(A ÷ 1.05, F) ), C )
月节省 = 基本电费(A_0) − 基本电费(A_1)
```

基本电费用第 1 节的算式。充电功率加在负荷上，所以夜间充电如果把负荷抬得比放电后的峰值还高，节省会相应减少。按容量计费的用户没有这项节省，除非同步办理减容。

**第 5 步，最低峰值求解，可选。** 给了负荷曲线、储能功率和容量，想知道峰值最低能压到多少时，求最小的 T，使放电窗口内 Σ max(load_t − T, 0) ≤ capacity × dod，并且 max(load_t − T) ≤ power。Σ max(load_t − T, 0) 随 T 连续、分段线性、单调下降，可以用二分法求。求得的 T 代入第 4 步，夜间充电的功率仍要加回去。

### 6.4 常数与参数表

| 项 | 值 | 性质 | 出处 |
|---|---|---|---|
| 效率、放电深度、循环寿命、投资、运维 | 没有默认值 | 用户或厂商参数 | 无 |
| 充电价、放电价 | 没有默认值 | 用户输入，取本省分时电价表或零售合同 | 无 |

### 6.7 地方差异与不确定

- 循环寿命按什么工况标定，由厂商定义。本规格把 `cycle_life` 理解为在 `dod` 下的循环次数。厂商按 100% 深度标定而实际深度更低时，寿命会偏长，本规格不做换算。
- 一天两次循环而充放电价不同的，本规格只支持一组充放电价。要分开算的，按两种循环各算一次再相加。
- 各省分时电价的时段和价格没有内置。用户只报省份时，请其给出充放电价。
- 用户侧储能参与需求响应、辅助服务的收益不在本计算器内。

## 7. 负荷平移与蓄冷蓄热的日收益

### 7.1 用途与适用对象

执行分时电价的工商业用户，把可移负荷从高价时段挪到低价时段，或者用蓄冷、蓄热设备在低价时段充蓄、高价时段放蓄。本计算器测算每天的收益，以及保本需要的价差比。

### 7.2 输入参数

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `energy` | 要移动的电量 q。直接平移时是源时段减掉的用电量；蓄冷蓄热时是高峰时段要省下的用电量 | kWh | 是 | 移 2000 千瓦时；蓄冷 3000 千瓦时 |
| `source_price` | 源时段的电价，即高价时段的电价 | 元/kWh | 是 | 尖峰 1.2 元 |
| `target_price` | 目标时段的电价，即低价时段的电价 | 元/kWh | 是 | 低谷 0.3 元 |
| `efficiency` | 蓄能效率 η_s，放出的冷或热折合的电量与充进去的电量之比 | 小数 | 蓄冷蓄热时必填；直接平移时等于 1 | 蓄冷效率 90% |
| `aux_charge` | 充蓄时段的辅助用电，占充蓄电量的比例 a_c | 小数 | 否，缺省 0 | 充蓄时水泵耗电 5% |
| `aux_discharge` | 放蓄时段的辅助用电，占充蓄电量的比例 a_d | 小数 | 否，缺省 0 | 放冷时风机耗电 5% |
| `max_energy` | 可移负荷的上限 | kWh | 否 | 设备 400 千瓦，可停 3 小时，即 1200 千瓦时 |
| `demand_before`、`demand_after`、`demand_price` | 平移前后的最大需量和需量电价 | kW、kW、元/(kW·月) | 否 | 平移后最大需量会到 1900 千瓦 |
| `days` | 当月天数，算月净收益用 | 天 | 否 | 按 30 天算 |

必须拒绝的输入：电量不大于 0；源时段电价不大于 0；效率不大于 0 或大于 1；效率减去 a_d 后不大于 0。

### 7.3 计算步骤

**直接平移。** 不给效率，或效率等于 1 且没有辅助用电时：

```
日收益 = q × (P_src − P_dst)
```

**蓄冷蓄热。**

```
充蓄电量 E_in = q ÷ η_s
日收益 = q × P_src − E_in × (1 + a_c) × P_dst − E_in × a_d × P_src
临界价差比   = (1 + a_c) ÷ (η_s − a_d)
临界源时段电价 = P_dst × 临界价差比
```

E_in × (1 + a_c) 是充蓄时段从电网取的总电量，按目标时段的电价计。E_in × a_d 是放蓄时段的辅助用电，按源时段的电价计。当前价差比是 P_src ÷ P_dst，不低于临界价差比时才划算。

| 条件 | 结论 |
|---|---|
| 日收益大于 0 | 划算 |
| 日收益等于 0 | 持平 |
| 日收益小于 0 | 不划算，除非电价差扩大到临界点以上 |
| q 大于 `max_energy` | 按 `max_energy` 计算，并提示只能移这么多 |
| `demand_after` 大于 `demand_before` | 提示会抬高最大需量。给了需量电价的，按第 1 节的算式算出需量电费的增加额，从收益里扣掉 |

需量电费用第 6 节第 4 步的核定值算法，即 D* = min( ceil_step( max(A ÷ 1.05, F) ), C )。月净收益 = 日收益 × `days` − 需量电费增加额。工艺上能不能移、移到哪几个小时，由用户判断，程序不排时段。

## 8. 发电侧结算差异桥

### 8.1 用途与适用对象

发电企业的交易员做 T+1 或月度复盘时，把实际利润相对基准情景的差异，精确拆到九个科目，残差为 0。基准情景可以是交易计划、前一版估算或复盘时的对照情景。适用范围是一个结算时段；多时段的逐时段拆开再汇总。

### 8.2 输入参数

每个情景一组，基准和实际各一组。下表以元/兆瓦时和兆瓦时为例，程序内部换成千瓦时和元/千瓦时。

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `contract_energy` | 合约电量 | kWh | 是，没有合约为 0 | 合约 8 万千瓦时；合约 80 兆瓦时 |
| `contract_price` | 合约价格 | 元/kWh | 有合约时必填 | 合约价 350 元/兆瓦时 |
| `dayahead_energy` | 日前市场出清电量 | kWh | 是 | 日前出清 25 万千瓦时 |
| `dayahead_price` | 日前市场的节点或分区边际电价 | 元/kWh | 是 | 日前价 300 元/兆瓦时 |
| `actual_energy` | 实际上网电量 | kWh | 是 | 实际上网 26 万千瓦时 |
| `realtime_price` | 实时市场的节点或分区边际电价 | 元/kWh | 是 | 实时价 380 元/兆瓦时 |
| `reference_price` | 中长期结算参考点的现货电价 | 元/kWh | 否，缺省等于日前价 | 参考点价 310 元/兆瓦时 |
| `variable_cost` | 单位变动成本 | 元/kWh | 否，缺省 0 | 变动成本 230 元/兆瓦时 |
| `assessment` | 考核金额 | 元 | 否，缺省 0 | 考核 1500 元 |
| `allocation` | 分摊金额 | 元 | 否，缺省 0 | 分摊 400 元 |

两个情景在话里用「计划」「实际」，或「基准」「本月」这样的词分开。只给一组的，另一组按零处理之前要先追问。

必须拒绝的输入：任一电量为负；缺少基准或实际的一组电量。

### 8.3 计算步骤

**收入。** 一个情景的电能量电费：

```
R = Q_c × P_c + (Q_da − Q_c) × P_da + (Q_a − Q_da) × P_rt
```

Q_c 是合约电量，P_c 是合约价格，Q_da 是日前出清电量，P_da 是日前价，Q_a 是实际上网电量，P_rt 是实时价。这是 1217号第九十一条第（二）项方式二，在中长期结算参考点的价格等于日前价时的形式（A8）。参考点价格不等于日前价时，把 P_c 换成 P_c + P_da − P_ref。

**利润。**

```
Π = R − v × Q_a − 考核 − 分摊
```

**分解。** 从基准出发，依次把各个因素换成实际的值，每一步的增量记到一个科目。顺序固定：合约量、合约价、日前价、实时价、日前量、实际量。下标 0 是基准，1 是实际。

```
合约量效应 = (Q_c1 − Q_c0) × (P_c0 − P_da0)
合约价效应 = Q_c1 × (P_c1 − P_c0)
日前价效应 = (Q_da0 − Q_c1) × (P_da1 − P_da0)
实时价效应 = (Q_a0 − Q_da0) × (P_rt1 − P_rt0)
日前量效应 = (Q_da1 − Q_da0) × P_da1
实时量效应 = [(Q_a1 − Q_a0) − (Q_da1 − Q_da0)] × P_rt1
成本效应   = −[(Q_a1 − Q_a0) × v_0 + Q_a1 × (v_1 − v_0)]
考核效应   = −(考核_1 − 考核_0)
分摊效应   = −(分摊_1 − 分摊_0)
```

九个效应之和等于 Π_1 − Π_0。每一步只换一个因素，前后两步的差逐个相加正好抵消，所以残差恒为 0。算式里没有除法，用 `decimal` 计算是精确的。

日前量效应和实时量效应的拆法：日前多出清的部分按日前价计，实际与日前的偏差按实时价计。两者相加，等于这一步沿路径得到的增量 (Q_da1 − Q_da0) × (P_da1 − P_rt1) + (Q_a1 − Q_a0) × P_rt1。

**舍入尾差。** 各科目分别舍入到分以后相加，可能与「实际利润 − 基准利润」的舍入值差 1 分。输出加一行「舍入尾差」，等于 Round(Δ) 减去各科目舍入值之和。程序内的 `Residual` 用未舍入的值算，恒为 0，测试断言用它。

**多时段。** 逐时段各做一次分解，再按科目相加。恒等式对每个时段成立，对汇总也成立。

### 8.7 地方差异与不确定

- 分解顺序是口径。
- 本桥按方式二设科目。所在省按方式一结算的，收入总额相同，科目的分法不同。
- 《电力现货市场基本规则（试行）》自定的有效期到 2026 年 10 月 15 日为止。修订稿于 2026 年 10 月 19 日起公开征求意见，截至 2026 年 11 月 26 日未见正式印发。新版发布后要核对结算公式。

## 9. 申报前规则校验

### 9.1 用途与适用对象

交易员在提交申报之前，用合约量、申报量和预计的实际电量，对照允许偏差的范围，判断会不会触发偏差考核，并给出可申报的区间和最坏情况下的考核金额。适用于日前申报、月度分解计划等。使用者是电力用户、售电公司、发电企业的交易员。

### 9.2 输入参数

| 字段 | 含义 | 单位 | 必填 | 用户话里的常见写法 |
|---|---|---|---|---|
| `contract_energy` | 考核的基准量，通常是合约电量 | kWh | 是 | 合约 100 万千瓦时 |
| `declared_energy` | 打算申报的电量 | kWh | 是 | 打算报 108 万千瓦时 |
| `allowed_down` | 允许下偏的比例 | 小数 | 是 | 允许偏差 ±5%；下偏不超过 3% |
| `allowed_up` | 允许上偏的比例 | 小数 | 否，缺省等于 `allowed_down` | 上偏 5% |
| `forecast_low`、`forecast_high` | 预计实际电量的下限和上限。只给一个数时，两者相同 | kWh | 否 | 预计实际 46 万到 54 万千瓦时 |
| `assess_price`、`assess_rate` | 考核电价和考核比例，与现有偏差计算器的字段相同。只给考核单价时，考核比例取 1 | 元/kWh、小数 | 算考核金额时必填 | 超带部分按现货价 0.4 元的 10% 考核；每千瓦时 0.05 元 |
| `basis` | 考核的对象 | 文本 | 否，缺省是「申报量对合约量」 | 按实际用电对合约考核 |
| `province` | 省份或市场的名称 | 文本 | 否 | 湖南；山东现货。只用来标注参数的来源 |

`contract_energy`、`assess_price`、`assess_rate` 沿用现有的字段。`allowed_down`、`allowed_up` 是新增的，现有的 `allowed_rate` 只能表示对称的范围。

必须拒绝的输入：合约量不大于 0；比例为负；下偏比例不小于 1。

### 9.3 计算步骤

```
带下界 L = Q_c × (1 − allowed_down)
带上界 U = Q_c × (1 + allowed_up)
```

对待检查的每一个电量 X 做同样的计算。X 是申报量，以及用户给了的预计下限和预计上限。

```
偏差电量     = X − Q_c
偏差率       = (X − Q_c) ÷ Q_c
低于下界的量 = max(L − X, 0)
高于上界的量 = max(X − U, 0)
超带电量     = 低于下界的量 + 高于上界的量
带内余量     = X 不高于 Q_c 时为 X − L，否则为 U − X
考核金额     = 超带电量 × assess_price × assess_rate
```

考核金额的算式与现有的 `assessDeviation` 相同，只对带外的电量计。带内余量在带外时是负数，它的绝对值就是超带电量。

| 给了什么 | 条件 | 结论 |
|---|---|---|
| 只有申报量 | 超带电量为 0 | 按你给的范围，申报量在带内，不触发 |
| 只有申报量 | 超带电量大于 0 | 申报量超出允许范围，考核金额如所算 |
| 给了预计区间 | 下限和上限都在带内 | 预计不触发 |
| 给了预计区间 | 任一端在带外 | 可能触发。最坏超带电量取两端中的大者 |
| 任何情形 | X 恰好等于 L 或 U | 按含边界处理，算带内 |

申报量超带时，给出可申报的区间 [L, U]，以及申报量最多能调到多少。

国家文件里没有全国统一的允许偏差范围和考核标准。1656号的文字版全文里，「偏差」只出现在偏差电量结算、绿电环境价值偏差补偿和风险分类的条文里，没有数值。976号只规定零售合同要填报考核条款。现货市场的偏差电量本身按现货价格结算（A8 第八十四条、第六十二条），此外有没有考核、范围多大，由各省规则和合同约定。手册〈省级规则的作用〉也注明，偏差处理等具体规定在省级文件里。

### 9.5 各省参数不同时的处理方式

1. 不内置任何省份的允许偏差范围、考核标准、考核对象和考核周期。计算器只接受用户在对话里给出的参数。
2. 参数随会话保存。用户换了一个省，必须重新给参数，不复用上一个省的。
3. 输出里列出用到的每一个参数和它的来源。来源固定写成「用户提供，未核对现行规则」。用户给了文号或生效日期的，原样显示。
4. 用户只报省份、不给参数时，回答该省现行的允许偏差范围和考核标准需要用户提供，不猜数。
5. 支持不对称的范围，支持逐月的表格输入。
6. 考核的对象由用户选，不替用户决定。
7. `province` 只是标签。以后要接入经官方核对的省级参数表，另立数据文件，每条带文号、生效日期和网址。没有这些的条目不得进入。

### 9.8 地方差异与不确定

## 附录 C 与上一轮算例的差异

上一轮的算例在 `research/skills-trading-ideas.md` 第 2 节。本规格沿用了那些数，下面几处的数值或口径有变化，以本规格为准。

- 功率因数补偿量：上一轮写 54,704 千乏时。按 tan φ 的精确值算是 54,703.37，差别来自上一轮把 tan φ 取了四位小数。
- 补偿后的功率因数 0.9662：上一轮取 0.96，是截尾。本规格四舍五入取 0.97。取整规则没有官方原文，所以输出要带未取整值。
- 保本点：上一轮把担保资金成本按每千瓦时 0.0001 估。按 30,000 × 1% ÷ 3,600,000 精确算是 0.0000833，对应的度电净利是 0.0409167，年净利 147,300 元，保本现货价 0.8046，安全垫 34.10%。不含资金成本时分别是 0.041、147,600 元、0.805、34.17%。本规格把两种情况分成用例 5-1 和 5-2。
- 盈亏平衡需量：上一轮只给了 1280 千瓦。本规格另给贴线口径的 1344 千瓦，并说明两个值之间取决于核定值怎么报。
- 差异桥：数值与上一轮一致。本规格写明了分解的顺序，并补了合约量、合约价变化时的两个算式。
- 申报前校验：上一轮写的是报价曲线的校验，查限价、段数和单调性。本规格按这次任务的要求，收窄为申报量对合约量的偏差校验。
