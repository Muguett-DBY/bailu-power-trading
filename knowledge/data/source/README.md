## 3. 数据结构

两份 JSON 都有的顶层字段：`document`（来源文件全称与文号）、`effectiveFrom`（施行日期）、`source`（附件网址）、`fetchedAt`（抓取日期）、`items`（记录）、`notes`（表注）、`complete`。
**每条记录自带来源信息**：省份、参数名、值、单位、适用对象、来源文件全称与文号、来源网址、页码和表名。

`items` 是主数据，**一个数值一条记录**，共 593 条：

| 字段 | 含义 | 例 |
| --- | --- | --- |

每张表的列位置各不相同，脚本对每一页单独求：把 `pdftotext -bbox-layout` 给出的所有价格词按 x 中心聚类，每一簇是一列；表头里离某列最近的词就是该列的标签。以北京（第 1 页，单位 pt，页面宽 841.9）为例：

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 列中心 x | 187.4 | 247.4 | 307.3 | 367.2 | 428.5 | 490.8 | 553.0 | 615.3 | 677.6 | 740.0 |

同一列里数字的中心对齐到 0.5 pt 以内（解析脚本对每列断言）。表头的词要先按很小的间距并成段再归列：全角括号的字框有一半是空白，甘肃表需量列的「）」如果单独按字框中心归列会落到隔壁「35千伏」列。

## 7. 文本和数字的处理约定

- **数字**：JSON 里是数字类型，小数位数与原文相同（原文 `0.2050` 就写 `0.2050`，`52.0` 就写 `52.0`）。A 的电量电价原文一律 4 位小数，需量、容量电价一律 1 位小数；B 是整数。
- **空格**：这份 PDF 是 WPS 导出的，每个字形单独定位，表格和表注所用字体（仿宋、Times New Roman）的子集里没有空格字形，`pdftotext` 在汉字和数字之间插的空格（如 `220 千伏`、`线损率为 3.11%`）是排版间距。所以列标签、用电分类、表注里的这种空格都去掉了：`不满1千伏`、`1~10（20）千伏`、`省内上网环节线损率为3.11%`。原样文本保留在 `raw` 里。
- **字符**：`1~10` 里是 ASCII 波浪号（U+007E）；括号是全角「（）」；深圳表需量、容量两列表头里的斜杠是全角「／」（U+FF0F），其余都是半角「/」。做字符串匹配时注意。
- **折行**：表注在 PDF 里按版面折行，数据里接回一条，不插空格；去掉开头的「注：」，保留编号，一条一个字符串。
- **`raw`**：该行数值在 `pdftotext -layout` 输出里的原始文本行（去首尾空白），保留原有空格。深圳一、二类的电量电价行用换行符接上了需量、容量所在的合并单元格行。
- **`province`** 是整理者加的省份名，原文用的是电网名：河北电网、冀北电网 → 河北；蒙东电网、蒙西电网 → 内蒙古；广东电网、深圳电网 → 广东；陕西两张表 → 陕西（B 同理：冀北 → 河北，蒙东、蒙西 → 内蒙古，深圳 → 广东）。`grid` 字段保留原文的电网名。

## 8. 抓取与解析方法

- 只用命令行：`pdftotext`（poppler 26.10，本机已有）和 `uv run --frozen --no-sync python -I` 跑自己写的只读脚本。没有打开窗口，没有安装软件，没有联网抓取任务以外的来源。
- 下载的文件各自放在系统临时目录下独立的新目录里，只当数据读；脚本放在另一个目录。
- 每份来源做三种抽取并对照：`pdftotext -layout`、`pdftotext`（不带 -layout，内容流顺序）、`pdftotext -bbox-layout`（每个词的坐标）。
- 以坐标为主解析（第 5 节），没有任何一张表是手工录入的。人工做的是：通读 34 页的 layout 文本弄清版式，以及把 6 页版式特殊的页面渲染成图片逐一目检（第 1、6、8、22、29、31 页：北京、蒙东、辽宁、深圳、陕西不含榆林、甘肃），都与数据一致。
- 脚本在本目录，需要 `pdftotext` 在 PATH 上：

```
python -I extract-transmission.py   <附件1.pdf>   <输出.json> <工作目录>
python -I extract-coal-capacity.py  <B附件.pdf>   <输出.json> <工作目录>
python -I extract-verify.py <data_dir> <work_dir> <A附件1.pdf> <A附件1.ofd> <526号附件1.pdf> <B附件.pdf> <extract-transmission.py> [README.md]
```

- `extract-transmission.py` 每解析完一页就把 JSON 重写一遍，所以文件总是完整可读的；顶层 `complete` 不是 `true` 或 `parsedPageCount` 小于 34 说明没跑完。
- `extract-coal-capacity.py`：表是左右两栏，每个数字找同一行带内、左边最近的词作名称（原表偶数行的数字比名称高约 3 pt，不能按「同一行」配对）。
- OFD 版（官网同一附件的另一种格式）是 pdf2ofdlib 从同一 PDF 转出的，有三处与原 PDF 不一一对应，核验脚本都做了处理：文本框宽度不是实际字宽；一行里相邻的数字被并成一个字符串；个别数字被拆成两块（冀北的 0.1803 是「0.180」加「3」）。

## 9. 核验方法与结果

A 的每个数字要过下面几关，哪一关不过，该表就记「有问题」：

| 关 | 做什么 |
| --- | --- |
| L | `pdftotext -layout` 文本：该页表注之前的全部数字与 JSON 记录逐个相同（多重集），小数位数原样；再由 JSON 的列标签和行拼出每个数据行的数字序列，与 layout 的数据行逐行相同（行数、每行数值个数） |
| R | 内容流顺序文本（不带 -layout）：表注之前的数字多重集相同 |
| O | OFD 版：每个数字串在 OFD 里的左边缘、上边缘与 pdftotext 的坐标相差不超过 1.5 pt；并只用 OFD 坐标把每列标签另推一遍，与 JSON 相同 |
| N | 表注：JSON 各条表注接起来，等于 layout 文本「注：」以后去掉全部空白 |
